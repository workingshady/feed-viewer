# Vercel Rebuild + Sources & Versions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Feed Viewer Pro deployable on Vercel Hobby + Neon + Vercel Blob. Make the applied feed version of each source the single source of truth for listings, add a Sources & Versions page, and remove local-only, insecure and dead code.

**Architecture:** The Vite SPA is served by Vercel. One Express app runs as the Vercel Function `api/index.ts` and only stores metadata (users, sessions, sources, versions, prefs, audit) in Postgres via Prisma. Browsers parse XML with the existing `xmlParser.ts`, upload the gzipped raw XML and the gzipped parsed listings straight to Vercel Blob (client upload tokens), then register a version. Every page reads listings through `useAppData()`, which loads the live version blob of each source via react-query.

**Tech Stack:** React 18, Vite 5, TanStack Query 5, shadcn/Radix, Express 4, Prisma 6 + Postgres 16 (Neon in production), `@vercel/blob`, fflate, Vitest 3 + supertest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-23-vercel-rebuild-design.md`, which executors must read alongside this plan.

## Global Constraints

- **Hosting and services:**
  - Free tiers only: Vercel Hobby, Neon free, Vercel Blob (Hobby).
  - Vercel request and response bodies must stay under 4.5 MB, so no API route accepts or returns file contents.
- **Roles:**
  - Exactly `admin`, `editor` and `viewer`, ranked `viewer < editor < admin`.
  - Enforced on the server for every mutating route.
- **Accounts and copy:**
  - No default or seeded account, password or credential anywhere: code, README, UI, tests (tests create their own users).
  - Login and signup pages contain only: title, fields, submit button, link to the other page, error text.
- **Signup:**
  - The first user ever becomes `admin`.
  - After that, signup is allowed only when `ALLOW_SIGNUP=true`, and new users are `viewer`.
- **Login rate limit:** 5 failed attempts per username or per IP in 15 minutes → HTTP 429 `{error:"too_many_attempts"}`.
- **Versions:**
  - Safety rule: do not auto-apply a new version when `newCount < 0.7 * liveCount` (live > 0).
  - Retention default: 5 versions per source. Pinned versions and the live version are never pruned.
  - Blob paths: `sources/<sourceId>/<uploadId>/feed.xml.gz` and `sources/<sourceId>/<uploadId>/listings.json.gz`.
- **Errors and stack:**
  - The 500 response body is exactly `{"error":"server_error"}`.
  - Postgres only, with migrations via `prisma migrate`. No `db push` and no DDL at runtime.
- **Tooling:** npm is the only package manager, and there is one root `package.json`.

## Review Focus

1. **Uploading the exact same file twice for a source.** Expect no new version: respond 200 with the existing version and `duplicate: true`, and show "already uploaded as vN" in the UI. Pinned in Task 6.
2. **An XML whose agency name matches no source, or has no agency block.** Expect the upload dialog to ask you to pick or create a source; never silently create "Unknown". Pinned in Task 11 (`matchSource`).
3. **A blob upload succeeds but registering the version fails** (network or 4xx). Expect the orphaned blobs to be deleted and an error shown. No half-version row should exist. Pinned in Task 11.
4. **Applying or deleting from one tab while another tab shows the old version.** Expect the other tab to update on focus, and a delete of an already-deleted version to return 404, which the UI handles as "already removed". Pinned in Tasks 6 and 12.
5. **Deleting the last remaining source.** Expect every page to show the empty state that links to `/sources`, with no crash on empty `listingsByAgency`. Pinned in Task 15.

  - `hasRole(user: {role: Role}, min: Role): boolean`.
  - `signupDecision(userCount: number, allowSignup: boolean)` returns `{ allowed: true; role: Role } | { allowed: false }`:

  - `authMiddleware` reads the `sid` cookie, loads the session and user, and slides `expiresAt` when more than 1 day has elapsed since `lastSeenAt`. There is no in-memory cache.
  - `requireRole(min: Role)` responds 401 `{error:"unauthorized"}` without a user and 403 `{error:"forbidden"}` when the rank is too low.
  - `createSession(res, userId)`; `destroySession(req, res)`.
  - The cookie is `sid`, `httpOnly`, `sameSite:"lax"`, `secure: NODE_ENV==="production"`, `path:"/"`, with `maxAge` from `SESSION_TTL_DAYS`.
  - `type AuthedRequest = Request & { user?: { id: string; username: string; role: Role } }`.
- **Routes (`/api/auth`):**
  - `GET /me` → `{user: {id, username, role, createdAt} | null}`.
  - `GET /signup-status` → `{open: boolean, firstUser: boolean}`, used by the UI to show or hide signup.
  - `POST /register {username, password}` returns 201 `{user}` and sets the cookie. It responds 403 `{error:"signup_closed"}` when closed and 409 `{error:"username_taken"}` for a duplicate. Validation: username 3–32 characters matching `[A-Za-z0-9_-]`; password 8–256 characters. User count and creation run in one `$transaction` with `Serializable` isolation, so two concurrent first signups cannot both become admin.
  - `POST /login {username, password}`:
    - responds 429 `{error:"too_many_attempts"}` when rate limited, checked before the password;
    - responds 401 `{error:"invalid_credentials"}` for an unknown user or a wrong password, and records a `LoginAttempt`;
    - returns 200 `{user}` on success.
  - `POST /logout` → `{ok:true}`.
- **Audit:** `recordAudit(userId: string | null, action: string, targetType: string, targetId: string | null, meta?: object): Promise<void>`. Actions use the pattern `auth.register`, `source.delete`, `version.apply`, and so on.

### Task 6: Sources and versions API, blob store, upload tokens

**Files:**
- Create: `server/src/sources/policy.ts`, `server/src/sources/routes.ts`, `server/src/sources/blobStore.ts`, `server/src/blob/routes.ts`, `server/test/sourcesPolicy.test.ts`, `server/test/sources.test.ts`

**Interfaces:**
- **Pure (`policy.ts`):**
  - `decideAutoApply(liveCount: number | null, newCount: number): { apply: boolean; reason?: "count_drop" }` returns `apply:false, reason:"count_drop"` iff `liveCount && liveCount > 0 && newCount < 0.7 * liveCount`.
  - `selectVersionsToPrune(versions: {id: string; number: number; pinned: boolean}[], retain: number, liveId: string | null): string[]` returns the oldest non-pinned, non-live versions beyond the `retain` most recent (pinned and live versions count toward `retain`).
- **`BlobStore`:** `{ del(urls: string[]): Promise<void> }`.
  - `vercelBlobStore` uses `del` from `@vercel/blob`; empty arrays are a no-op.
  - Tests use a `FakeBlobStore` that records the URLs.
- **DTOs** (also mirrored in `src/lib/sourcesApi.ts`):
  - `SourceDTO { id, name, agencyName, agencyInfo, mapping, activeVersionId, retainVersions, createdAt, updatedAt, versions: VersionDTO[] }`, with versions newest first.
  - `VersionDTO { id, number, status, fileName, fileBytes, sha256, uploadId, xmlBlobUrl, listingsBlobUrl, listingCount, added, removed, changed, warnings, note, pinned, mappingFingerprint, createdAt, createdBy: {id, username} | null }`.
  - Add `mappingFingerprint String?` to `FeedVersion`, with a new migration `add_mapping_fingerprint`. Change the unique constraint to `@@unique([sourceId, sha256, mappingFingerprint])`.
- **Routes (`/api/sources`):** reads need `viewer`; everything else needs `editor`.
  - `GET /` → `{sources: SourceDTO[]}`.
  - `POST / {name, agencyName, agencyInfo?}` → 201 `{source}`. A duplicate name → 409 `{error:"name_taken"}`.
  - `PATCH /:id {name?, mapping?, retainVersions? (1..50)}` → `{source}`.
  - `DELETE /:id` deletes all version blobs, then the row → `{ok:true, deletedVersions: n}`.
  - `POST /:id/versions {uploadId, fileName, fileBytes, sha256, mappingFingerprint, xmlBlobUrl, listingsBlobUrl, listingCount, added, removed, changed, warnings, apply: "auto" | "never"}`:
    - A duplicate `(sha256, mappingFingerprint)` returns 200 `{version: existing, duplicate: true, applied: false}`, and the server deletes the newly uploaded blobs.
    - Otherwise it creates a version with `number = max + 1` inside a transaction. When `apply==="auto"`, it calls `decideAutoApply(liveVersion?.listingCount ?? null, listingCount)` and sets the live version if allowed. It then prunes with `selectVersionsToPrune`, deletes the pruned blobs, and records audit events.
    - Response: 201 `{version, duplicate:false, applied: boolean, blockedReason?: "count_drop", pruned: string[]}`.
    - Blob URLs must start with `https://` and contain `/sources/<id>/`; otherwise 400 `{error:"invalid_blob_url"}`.
  - `POST /:id/versions/:vid/apply` → `{source}`.
  - `PATCH /:id/versions/:vid {note?: string (≤200), pinned?: boolean}` → `{version}`.
  - `DELETE /:id/versions/:vid` responds 409 `{error:"version_is_live"}` when the version is live. Otherwise it deletes the blobs and the row → `{ok:true}`. An unknown version → 404.
- **`/api/blob/upload`** (`POST`, `requireRole("editor")`): uses `handleUpload` from `@vercel/blob/client`.
  - `onBeforeGenerateToken(pathname)` requires `pathname` to match `^sources/[a-z0-9]+/[A-Za-z0-9_-]{10,}/(feed\.xml|listings\.json)\.gz$` and the source to exist, then returns `{ allowedContentTypes: ["application/gzip"], maximumSizeInBytes: 50 * 1024 * 1024, addRandomSuffix: true }`.
  - `onUploadCompleted` is a no-op, because registration is explicit.
  - Not unit-tested against Vercel. Test the pathname validator as a pure `isAllowedBlobPath(pathname)` exported from `blob/routes.ts`.
